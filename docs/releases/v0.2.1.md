# Doors 0.2.1 release notes

Released 2026-09-28 (tag `v0.2.1`). The image is the build of `9dc66c2`:
`doors-0.2.1-tdisplay-k230-9dc66c2.img.gz`, sha256
`326e084b63a282c99fb16226a418605ad8bb8f9456b8c4d2e52f751d5eeea212`
(raw `sysimage-sdcard.img`, 763,363,328 bytes, sha256
`c6ef54921e542f7290ac1a0decbe5862ea443b3f2234f4f5f6523635446ef2ef`). The
commits after `9dc66c2` are documentation only.

Doors 0.2.1 follows v0.2.0 (tag `v0.2.0`, 2026-09-28), which stays as it was:
its tag and its image are unchanged. It has one change: the image now
carries Vision's model, so Vision works right after a fresh flash.

Doors' own licence is not decided. No licence is granted and redistribution of
Doors, as source or as an image, is not authorised (docs/LICENSING.md).
**This image also contains AGPL-3.0 material (the Vision model, below) and is
for internal development and testing only.**

## What changed since v0.2.0

- **The Vision model is in the image.** The `pocketos` package installs the
  pinned vendor SDK's `yolov8n.kmodel` (3,495,296 bytes, sha256
  `0b4bcdd3eef7ad05d827127ec630d2354659f6db1b0c627ecb4af32cb2004a09`) at
  `/usr/share/doors/vision/yolov8n.kmodel`, where `pos-vision` reads it. The
  file is copied from the SDK at build time and is not in the repository.
  The install refuses any file with a different hash, and refuses the model
  without its notice. v0.2.0 needed `tools/vision/install-model.sh` after
  every flash; that script remains for units on older images and for trying
  another model.
- **Its licence is recorded.** The model is Ultralytics YOLOv8n, which
  Ultralytics publishes under AGPL-3.0; the SDK names no terms for the file.
  On 2026-09-28 the owner decided to use it under the AGPL-3.0 in internal
  images only (docs/LICENSING.md item 10, which stays open for any
  distribution outside the project). THIRD_PARTY_NOTICES.txt has a new entry
  with the model's provenance and source, and the AGPL-3.0 text unchanged.

No code changed: `pos-vision`, the shell and the services are the v0.2.0
code, rebuilt with the new build identity.

## Upgrading from v0.2.0

As for v0.2.0: a flash replaces the whole card, including the SSH host key
and meshcored's identity, so save `/var/lib/pocketos`, `/etc/default` and
`/etc/pocketos` first and put them back. Nothing else is needed for Vision.

A unit that stays on v0.2.0 can get the same model with
`tools/vision/install-model.sh <unit ip>`.

## Rolling back

Flash the v0.2.0 image (tag `v0.2.0`), then install the model by hand if
Vision is wanted.

## Known limitations

As in v0.2.0, and:

- **Internal images only**: the image contains the AGPL-3.0 Vision model;
  distributing it outside the project needs docs/LICENSING.md item 10
  decided for that (and Doors' own licence, item 1).
- Vision's detection is weak in warm, dim indoor light, and its count can
  exceed the real crossings when tracks are lost and restarted (above).

The full list is docs/KNOWN_ISSUES.md.
