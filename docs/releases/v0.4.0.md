## New since v0.3.9

### Vision

- **The screen redesigned around the picture** (PR #130): the counters sit
  on the picture's top corners as chips, the picture is wider upright
  (500 to 528 px), MODE is a switcher of its own, and the picker lists every
  mode of its group with the ones the helper cannot run dimmed.
- **SEGMENT and INSTANCES** (PR #129): semantic segmentation (street
  classes) and instance segmentation (80 COCO classes) with ORIGINAL,
  OVERLAY and MASK views. **Neither model is part of Doors or this image**;
  a mode is offered only when its file has been put on the unit by hand
  (see "Models and licences").
- **INSTANCES colours each object by its track id** (PR #131), so two
  objects of one class get two colours and an object keeps its colour while
  it keeps its id.
- **GENERAL 365** (PR #132): an optional Objects365 detector (PP-YOLOE+ s)
  as a third choice under MODEL beside R0 and GENERAL 80. **Its weights are
  not part of Doors or this image.** Without the file nothing changes; R0
  stays the default and TRAFFIC's detector.
- **KPU memory fix** (PR #128): `pos-vision` released its CMA pool only for
  models that loaded and stayed open; describing or refusing a model lost
  about 8.9 MB of CMA per call until reboot (unit B). Fixed
  (docs/vision/KPU_CMA_LEAK.md).

### Relay Nine (PR #133)

- Graphics rebuilt for the Arcade Neon environment, with a cheaper
  renderer (bit-exact with the first version of the new art) and an economy
  controller that no longer cycles in and out.
- The scene is scaled in the app and drawn unscaled by LVGL. On unit A
  (gate route, master with #131 and #132 merged with the branch): frame
  interval p95 33.3-35.7 ms against master's 42.7-44.2 ms; LVGL draw p50
  0.48 ms against 7.2 ms. The scale buffer (735,368 B) is held only while
  the app is open.

### RotorTerror (PR #119)

- A new, original helicopter arcade game under **Games**: PILOT, ACE and
  TERROR difficulty, automatic cannon, steered rockets, three stage
  sceneries and a gunship every third wave (docs/apps/ROTORTERROR.md).

### RIFT (PR #124)

- ACTIVITY no longer reports direct messages crowded out of RIFT's window
  on a busy channel as unreadable; automatic capitals on the touch keyboard
  and the keyboard base; channel sender names drawn as typed, with one line
  saying channel names are not verified; larger touch targets.
  Checked on unit A (docs/hardware/RIFT_USABILITY_ROUND2_UNIT_A.md);
  nothing was transmitted.

### DeskBuddy (PR #121)

- Vision reports are counted by the session's own number instead of the
  camera's buffer sequence, which stays 0 on the K230. With v0.3.9's code
  DeskBuddy counted the first report and then fell to CAMERA UNAVAILABLE;
  unit B took every report for 3.5 minutes with the fix (2026-11-04). A
  real person's arrival, departure and return with the fix is still
  unchecked (Known limitations).

### Radio safety (PR #127)

- radiod refuses `radio.send` and `radio.send_async` while the radio
  profile is uncertain (a configure failed and restoring the previous one
  failed too), until a configure succeeds or the radio is switched off and
  on.
- A failed radio setup now also restores the stored on/off choice, and
  says "the previous settings are back" only when that is known to be true.
- `system.reboot` and `system.poweroff` are refused while a radio setup
  runs.

### Build (PR #115)

- **A clean SDK output builds.** Fortran stays selected for the external
  toolchain (Buildroot refuses one with an unselected language) and the
  package removes `libgfortran` after every build; `camera_rtsp_demo`
  creates `/root/app` itself. The image's Buildroot configuration changed
  for this (`BR2_TOOLCHAIN_EXTERNAL_FORTRAN=y`); the image still carries no
  `libgfortran`. **This candidate was built from a clean SDK output**
  ("Candidate image").

### Not in the image

- **Library** (PR #118), an offline Kiwix reader, is a feasibility
  prototype: it is left out of the shell unless built with
  `-DPOCKETOS_WITH_LIBRARY=ON`, and its helper (which links GPL libzim) is
  not built, installed or shipped (docs/apps/LIBRARY.md, ADR-015 proposed).
- Documentation-only PRs: #116, #117, #120, #122, #123.

## Upgrading from v0.3.9

As for every release, a flash replaces the whole card: save
`/var/lib/pocketos`, `/etc/default` and `/etc/pocketos` first. A locally
installed GENERAL 80, GENERAL 365, SEGMENT or INSTANCES file under
`/usr/share/doors/vision/` is not on the new card and has to be copied
again from a file the owner holds. Shell and `pos-vision` still speak
protocol 3 and are installed together by the image.

  not part of Doors; their hardware records are unit B's (VISION.md). The
  redesigned screen was checked on unit B by screenshots and keys, not by
  touch. SEGMENT in portrait is coarse (VISION.md, "Limits").

  portrait and landscape, the corners and the touch controls (fresh-card
  test); the Small and Large text sizes were not part of that check. Two LOW
  review items (fixed fonts, a 4 px overlap) are unchanged.
- **DeskBuddy:** a real person's arrival, departure and return with the
  report-counter fix is unchecked on hardware; owner-aware Guard is not
  implemented; #109 is unresolved.
- **Relay Nine has no launcher icon art or mask** (since 0.3.8); its tile
  falls back to a symbol. `app_icons_test` now says so (2 checks).
- **Terminal:** `term_session_test` fails its leftover-job checks on this
  PC's WSL host, at v0.3.9 as well; the code is unchanged since 2026-10-01;
  not diagnosed and not checked on a unit.
- **Design-rule lints failing since v0.3.9 or earlier:** `calendar_lint`
  (the selected style's fill) and `terminal_lint` (games using the raw-key

- **Launcher audit:** three untexted overlaps on the home screen, present

- Everything listed for v0.3.9 and earlier still applies unless fixed above
