# Doors 0.3.7 release notes

**Candidate, not released.** Release branch `release/v0.3.7`, cut from
master `8bfa66f` (PR #93) on 2026-10-17. Not tagged, not published.

Doors 0.3.7 follows v0.3.6 (tag `v0.3.6`, 2026-10-09). It is everything
merged to master since then. **NinjaOne is not part of it**: the NinjaOne
client is still the draft PR #84 (`feat/ninjaone-app`), and no NinjaOne code
is on master or in this image. (docs/hardware/VISION_HDMI_GATE.md mentions
NinjaOne only because unit B was running that branch during the HDMI gate.)

- **Image:** not built yet; recorded under "Release image" when it is.
- **Hardware:** the fresh-card smoke test
  (docs/hardware/V0.3.7_FRESH_CARD_TEST.md) has not been run.

## New since v0.3.6

### Vision on an HDMI monitor (PR #85)

- **The board's own HDMI device tree** (kernel patch 0075, ADR-011): the
  HDMI tree is now the panel tree with the RM69A10 panel and GT9895 touch
  replaced by the LT9611 bridge and its connector. The vendor tree it
  replaces had no camera sensor setup, no LoRa, no uart1 and no BOOT key.
  The vendor tree stays on the card as `k230-canmv-v3.dtb`. **This is the
  first release image with 0075.**
- **HDMI is chosen at boot**: `pos-display-boot hdmi && reboot`, and back
  with `pos-display-boot lcd && reboot`. No automatic switching, no reboot
  on unplug, no bridge register access.
- **The shell on an external display** runs upright at rotation 0 in the
  monitor's mode, with no corner insets. Portrait-only apps get a column the
  panel's width. Backgrounds are centred and the lock screen stays opaque.
- **Vision and Camera** follow a change of hold while the screen is open.
  Vision has keyboard navigation (a focus ring over the buttons, Enter,
  Esc/Back; DS §38.10).
- **Settings** describes the hold instead of the rotation on an external
  display, and warns on HDMI.
- Hardware: gated on unit B with an HDMI monitor, 2026-10-13/14, with a
  hand-installed tree and shell (docs/hardware/VISION_HDMI_GATE.md).
  Keyboard navigation on the device is untested.

### RIFT

- **MAP can show an OpenStreetMap basemap** behind its nodes (PR #82,
  ADR-009 Amendment 1). **BASEMAP is off by default.** When it is on, RIFT
  fetches only the standard OSM raster tiles that intersect the visible map
  and caches what was viewed; there is no offline pack, bulk download or
  prefetch. The fetching and decoding run in `pos-browser tiles`, outside
  the shell. Off, MAP is the graticule and fetches nothing.
- **Four correctness fixes** (PR #88): overlapping RESENDs no longer remove
  the wrong orphan; a late or overtaken `mesh.status` is no longer taken for
  a service restart; a message id that is not a whole number is refused;
  decoded basemap tiles expire with the disk cache.

### Battery telemetry (PR #83, #86, #87)

- **Read-only battery readings** from the keyboard base's BQ27220 gauge and
  BQ25896 charger: Controls tile, Settings > Power & Sleep BATTERY panel,
  and a Diagnostics Gauge row. Nothing is ever written to either chip.
- **No battery level is shown.** The gauge's configuration does not match
  the pack (design capacity is the TI default), so its state of charge is
  marked "Unvalidated" and Doors reports the level as unknown
  (docs/hardware/BATTERY_PROBE.md).
- Power & Sleep fits in landscape again with the panel (two compact lines),
  and a two-line stepper title no longer clips in portrait at Large text.

### DeskBuddy (PR #81)

- **Companion mode plays by touch alone**: a camera-free personality. No
  camera, model or vision provider is involved in that path; Companion
  never starts the camera. Guard and Night are unchanged.

### Help & Feedback (PR #93)

- **Settings > System > About > Help & Feedback** shows a QR code for the
  project's feedback form (Microsoft Forms), with an enlarged view. The QR
  is made on the unit, offline; the form is opened and submitted from the
  phone. Doors sends nothing and attaches no logs or identifiers
  (docs/apps/HELP_FEEDBACK.md). The QR uses the pinned LVGL's bundled
  encoder (MIT, in THIRD_PARTY_NOTICES.txt).

### Games

- **Poker** (PR #89, also in PR #85): a short table layout for a 1280 x 720
  external display, where the community cards were never drawn; cards
  shrink together on a short table.
- **Blackjack** (PR #90): every card index stays readable in long hands;
  a long hand wraps to a second line.
- **Solitaire** (PR #91): every tableau index stays readable in long
  columns; a column that still does not fit scrolls inside the table. A
  drag no longer counts as a tap.
- **Timber** (PR #92): pull-track travel is paid by the tick it happened
  in, so a delayed frame no longer turns a safe drag into a jolt, and a
  release before a tick keeps its movement.

## Upgrading from v0.3.6

As for every release, a flash replaces the whole card: save
`/var/lib/pocketos`, `/etc/default` and `/etc/pocketos` first and put them
back after the first boot.

- A card set to boot HDMI (`/boot/force_dtb`) boots the new Doors HDMI tree;
  `pos-display-boot lcd && reboot` returns to the panel.
- RIFT's BASEMAP starts off; nothing is fetched until it is turned on.

## Known limitations

- **HDMI** is chosen at boot only. Vision's keyboard navigation is untested
  on the device; Settings cannot be navigated on HDMI, where there is no touch; the
  Poker 720p layout was validated on the host only.
- **Battery:** no level is shown (gauge unvalidated), and Doors has no
  low-battery shutdown.
- **RIFT basemap** with Wi-Fi off or without a set clock is untested on
  hardware.
- **Help & Feedback:** scanning the code from the panel with a phone has
  not been confirmed on hardware.
- Everything listed for v0.3.6 still applies (docs/releases/v0.3.6.md,
  docs/KNOWN_ISSUES.md): R0 is a beta, DeskBuddy does not use R0, stopping
  a camera stream can freeze the unit, Poker deals a fresh table on a
  rotation.
