# PG 2048

A Pocket Games title: the sliding-tile puzzle 2048 on a 4 x 4 board.
Integrated for Doors v0.2.x on `feat/games-solitaire-blackjack-2048` (from
v0.2.1 `c9c2105`, 2026-09-28): imported byte for byte from `feature/game-2048` `10dcc4a`
(physically tested on unit A at `b94b020` on 2026-09-13, in the temporary
combined build `test/pocket-games-triple` `03a0fef`: PASS), then brought up
to the current frame - see "Doors integration" below. Not merged; not yet
on glass in this form.

## Ruleset

The standard game, as `apps/2048/engine/g2048_rules.h` states it:

- A move slides every tile as far as it goes toward one edge.
- Two tiles of equal value that meet merge into one of twice the value; the
  merged value is added to the score.
- A tile merges at most once per move: `2 2 2 2` becomes `4 4`, never `8`;
  `4 4 8` becomes `8 8`. Where three equal tiles meet, the two nearest the
  edge being moved toward merge (`2 2 2` left is `4 2`, right is `2 4`).
- A move that changes nothing is not a move: no tile appears, the move
  counter does not advance, no random draw is spent.
- After every real move one tile appears in a uniformly chosen empty cell:
  a 2 nine times in ten, a 4 one time in ten. A new game starts with two.
- Making 2048 wins. The player may keep going; the goal is reported once per
  game.
- The game is over when no move in any direction changes the board.
- Best score is the highest score reached, carried across games.

The engine is deterministic from a 32-bit seed (xorshift32, the generator
Fleet, Radar and Timber use, duplicated deliberately as they do). The seed is
chosen at the app boundary from the wall clock, the LVGL tick and the move
count.

## Controls

One logical key stream (DS 17.4): simulator keyboard, touch or physical
keyboard all arrive the same way. No touch keyboard is shown.

| Panel on screen | Key | Touch | Does |
| --- | --- | --- | --- |
| Play | arrows, `w a s d` (either case) | swipe anywhere between HUD and buttons | move |
| Play | `n` | NEW GAME | new game; asks first if the board has moves on it |
| Confirm | `n` | NEW GAME | start the new game |
| Confirm | Enter, Esc, Backspace | KEEP PLAYING (accent) | keep the board |
| Won | Enter, Esc | KEEP GOING (accent) | continue past 2048 |
| Won | `n` | NEW GAME | new game |
| Over | Enter, `n` | NEW GAME (accent) | new game |

Move keys and swipes do nothing while a question or result is up. A swipe
must travel a tenth of the board (at least 32 px) and be at least 1.5x longer
on its main axis than across it; a diagonal smear is ignored rather than
guessed. Buttons never take the focus, so taps and keys mix freely. In the
question the accent sits on the safe action (DS 17.5), and Enter takes it.

## Architecture

```
apps/2048/engine/g2048_rules.[ch]  rules: slide, merge, spawn, score, goal, end, validity
apps/2048/engine/g2048_rng.[ch]    xorshift32
apps/2048/g2048_store.[ch]         the save file (the only file I/O)
apps/2048/ui/g2048_view.[ch]       pure: key map, swipe, layout, tile look, motion curves
apps/2048/ui/g2048_board.[ch]      LVGL: one custom-draw board widget
apps/2048/g2048_app.[ch]           LVGL: HUD, controls, input, persistence glue
```

Rules know nothing of pixels, keys or screens: the board is sixteen logical
cells and a direction is a direction on it. The view model is also LVGL-free,
so everything a key, a finger or a size change does is host-tested.
`tests/g2048_lint.sh` enforces the split (engine: no LVGL, no I/O, no float,
no platform entropy; view: no LVGL, no I/O; only the store touches files; no
colour or font named; one key sink; layout from the view).

**Look.** Tiles are DS slabs in tokens only: `surface_raised` mixed toward
`accent_primary` by at most 88/255, secondary text on the 2, primary text
above it, and a 2 px `accent_primary` outline from 2048 up. The ceiling is
measured, not chosen: past roughly a third accent the fill lands where
neither light nor dark text reads (at 128/255 the best text is 3.5:1 in
Normal and 2.4:1 in Night across the five themes). `tests/g2048_theme_test.c`
holds the contract over 5 themes x 3 modes; worst ratios: tile text 5.41
Normal, 6.04 Outdoor, 3.12 Night; the 2 is 5.60 / 9.04 / 2.80. The number
always carries the meaning; the fill only helps (DS 2). Empty cells are
`surface`. The tile number uses the largest of hero-48, hero-40, app-title
and row-title that fits the tile it is drawn on.

**Motion.** A move slides for 100 ms (eased out), then merged tiles swell
4 px and settle and the new tile grows in over 90 ms. A key or swipe during
it finishes it first. With `reduced_motion=1` nothing animates.

## Persistence

`$POCKETOS_STATE_DIR/2048/game.v1` (default `/var/lib/pocketos/2048/`), 43
bytes little-endian: magic `PG48`, version 1, 16 exponents, score, best,
moves, generator state, flags (won, keep going, over), FNV-1a. The whole game
is kept, generator included, so a resumed game continues exactly as it would
have, new tiles included.

- Opening the app and not playing writes nothing.
- A move marks the game dirty; the shell's 1 Hz tick saves it. A game that
  ends or reaches 2048 is saved at once. Closing the app saves.
  A swipe never waits for the card.
- A finished game is not resumed; its best score is.
- A missing file starts a new game. A damaged, foreign, other-version or
  impossible file (`g2048_game_valid`) is refused, left in place, shown as
  "SAVED GAME UNREADABLE · NEW GAME", and replaced by the next save.
- A failed save shows "NOT SAVED · PLAY CONTINUES"; play continues.
- Writes are temp + fsync + rename, like the other app stores.

**Deviation pending the owner:** app-owned storage, the arrangement Fleet's
D2 approved for Fleet only (and Radar's D1 still awaits). No platform
storage service exists; nothing here needs one.

## Orientation

The shell gives a portrait or a landscape body (DS §21) and the app lays out
in whatever it gets, from `g2048_view_layout(w, h)` on every size change:
stacked when the area is taller than wide, board left and HUD and controls
right when wider. Landscape was first seen (in the simulator) for this
integration and needed no change: the board is about 430 px square in the
landscape body, a tile about 100 px. `tests/g2048_app_test.c` opens it in
landscape, plays by key and by swipe, asks the new-game question, and turns
back to portrait with the app open. Swipe directions are screen directions,
which holds because the shell rotates the display, not the app.

## Doors integration (2026-09-28)

What changed from the 2026-09-13 branch, and nothing else:

- **Registered** in the shell (`ui/shell/shell.c`) and shown by the launcher
  in PLAY after Fleet, Radar and Timber, in the games colour
  (`ui/shell/home_layout.c`).
- **Fullscreen** (`.chrome = POCKETOS_CHROME_NONE`), like Fleet, Radar and
  Timber: no status cluster over the game; the shell's header keeps the way
  back.
- **Icon**: a first-party launcher mask and portal icon (four tiles,
  `docs/design/doors-app-icons/svg/2048.svg`), drawn like Zabbix's, Browser's
  and Vision's. `.icon` stays only as the text fallback. Place and icon are
  for the owner to confirm.
- **Landscape** (DS §21): see "Orientation".
- **Tests**: the app test hosts the app in the current frame (the chrome
  height from `chrome.h`, not the retired status-bar constant) and gained a
  landscape section (`tests/games_frame.h`: every object inside the body,
  every button at least 64 px tall with its label whole); the shell suite runs
  every review state in both orientations; the lint checks the launcher
  table instead of the v0.0.9 tile grid.
- **Build**: `make games-test` runs the three games' host suites and lints on
  their own; the card palettes come from one CMake step
  (`games_card_palette`).

Lifecycle, checked for this integration: every LVGL object is under the body
the shell deletes; the root is the only object added to the focus group and
goes with it; the slide animation is deleted with the board widget (`lv_anim_delete` on its delete event); the app state is one `lv_malloc` freed in `destroy`. The
save is a few hundred bytes, written with `fsync` from the once-a-second tick
only when something changed, at the end of a game and on close - the same
pattern as Notes, Clock and Radar - so the UI thread never waits on more than
one small file.

## Known limitations

- The unit A physical test (2026-09-13) passed by eye. Swipe threshold,
  motion timing and tile contrast on the AMOLED (RGB565 banding of the tint
  ramp, DS feasibility H1) remain unmeasured; the numbers on the tiles carry
  the meaning regardless.
- Launcher: 21 apps with the three games, so the portrait launcher scrolls
  further (PLAY and DEVICE each take a second row). A Games folder is
  proposed separately on `feat/launcher-app-groups`.
- No undo, no statistics beyond the best score.
- Review states for screenshots: `PG2048_SCREEN=play|confirm|won|over`
  (fixed seed, never reads or writes the save file). Host renders in
  `docs/design/shots/pg2048-*.png` (play in ice Normal, Outdoor and slate
  Night; confirm in brass; won in carbon; over in olive).
