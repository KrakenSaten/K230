# PocketOS v0.0.7 block 2a: sysd on unit A (2026-09-09)

Block 2a put `sysd` on the device for the first time: the `S50sysd` init
script, the corrected `system.*` contract from the cold review of `dc2bc88`,
and the build identity in `/etc/pocketos-release`. This sheet is the hardware
validation of that block. **Read-only throughout: `system.*` v0 opens no
device node and changes nothing; no transmission at any step, and no image was
flashed.** Every command ran as root over SSH (key `pocketos-bench-2026-09-08`).

**Verdict: PASS.** Every correction block 2a claimed is observable on the
device, the init script starts and stops cleanly under supervision, and the
runtime directory's tmpfs behaviour is now confirmed end to end rather than
assumed.

## /run is a tmpfs

```
tmpfs /run tmpfs rw,nosuid,nodev,relatime,mode=755 0 0
```

VERIFIED, and confirmed behaviourally by the ghost test below. This is the
fact `system.status.services[].running` rests on: `running` is
`kill(pid, 0)`, which is only safe against pid reuse because a reboot cannot
leave a pid file behind. The mount type was already VERIFIED at bring-up
(BRINGUP_SESSION_2026-09-07 §10.1); what this sheet adds is that the runtime
directory is genuinely emptied across a reboot, and that the service table
follows.

`carrier: null` while an interface is down is the documented EINVAL case,
confirmed on hardware. `sit0` (the IPv6-in-IPv4 tunnel device) is new to this
sheet and is reported because the contract is "everything in
`/sys/class/net` except `lo`"; its `address` really is the four-byte
`00:00:00:00`, so a client must not assume a six-byte MAC.

## Observations (none are defects in block 2a)

- **Bench deployments arrived owned by the builder's uid.** `S50sysd`,
  `S60radiod`, `S90pocketos-shell`, `/usr/bin/pos` and `/usr/sbin/sysd` all
  showed uid/gid 1000 where the vendor's `S99showversion` is `root:root`.
  `deploy.sh`'s `tar` preserved the build host's ownership; a flashed image
  does not have this, because Buildroot assigns root ownership when it
  assembles the rootfs. Pre-existing behaviour that affected S60 and S90
  identically, found by this smoke and fixed in the same commit as this sheet
  (`--owner=0 --group=0 --numeric-owner`, with regression coverage in
  `tests/package_sync_test.sh`). Re-deploy to correct a board that already has
  uid-1000 files. **Confirmed fixed on hardware**: the next bench deployment
  (`792f754`) landed `/usr/bin/pos`, `/usr/bin/pos-supervise`,
  `/usr/sbin/sysd` and `/etc/init.d/S50sysd` owned `root root`, and unit A no
  longer carries any uid-1000 file from a deploy
  (docs/hardware/V0.0.7_BLOCK2B_SMOKE.md).
- **`S50sysd start` returns about 50 ms before the socket exists.** Inherent
  to the `nohup pos-supervise ... &` model and identical for `S60radiod`.
  Anything that starts sysd and immediately queries it must retry; the shell
  already goes through `shell_ipc_call_timeout`, so no consumer is affected.
- **The storage de-duplication fix is not exercised on this board.**
  `/proc/mounts` lists `/` exactly once (`/dev/root / ext4`) and `/boot` once,
  so the duplicate-mount case remains covered only by `tests/pocketsys_test.c`.
- **`cpu_percent` reads `0` on an idle board** (1.02 under light load). A
  screen must render that as 0 %, not as unknown.
- **Runtime pid-file mode follows the umask of whoever started the
  supervisor**: 0600 when started from an SSH session, 0644 when started by
  init after the reboot. Cosmetic; the sockets are 0660 in both cases.
