**Build incident, resolved.** The first attempt failed at the radiod link:
the RadioLib objects were "not compiled with -fPIC" and the linker
crashed. Cause: my host-side riscv64 validation earlier that morning had
compiled RadioLib in place in the main tree's `vendor/RadioLib/src`
(non-PIC objects, 06:22), and those 32 `.o`/`.d` files were copied into the
build checkout and synced into the package, where make kept them because
they were newer than the sources. Fix: the build products were deleted from
the build checkout only, the apply step re-synced the package with
`--delete`, and the second attempt compiled all 16 RadioLib objects fresh.
The exported image comes from the second attempt only. Two hygiene
follow-ups, not applied here because this was a build-only step: delete the
stale objects from `C:\K230\vendor\RadioLib\src` (they are git-ignored but
will poison the next golden-procedure build from the main tree), and make
`apply_to_sdk.sh` exclude `*.o`/`*.d` from the RadioLib sync. A third:
`platforms/k230/scripts/*.sh` are stored without the executable bit, so a
checkout on a POSIX filesystem must invoke them through `bash`.

## 6. Runtime changes expected on a device running this image

- SSH refuses the empty root password from the network; serial console
  login stays passwordless. `passwd` on serial (or an authorized key)
  enables SSH. Telnet listens on 127.0.0.1 only.
- radiod starts on the mock backend, EU868, 2 dBm, and prints
  `Starting radiod (mock, EU868, 2 dBm): OK`. A restart returns to 2 dBm
  (or `RADIOD_TX_POWER_DBM` from `/etc/default/radiod`). A start-up power
  outside the chip range or above 14 dBm makes radiod exit 2; pos-supervise
  then retries and gives up after five restarts (about 31 s).
- A radiod crash or restart no longer kills the shell; the shell reconnects
  on its next call. radiod itself already ignored SIGPIPE.
- `pos-hwcheck --lora` refuses (exit 3) while radiod runs the sx1262
  backend or any LoRa line has a consumer; otherwise it runs bounded and
  leaves no gpioset behind. The plain inventory is unchanged.
- Crash reports are named `crash-<name>-<time>-<pid>.txt`; the supervisor's
  run-time and restart window use `/proc/uptime`.
- Everything else, including the vendor launcher, panel switch, DRM/touch
  overrides, Fleet and Radar, is as in v0.0.1.

## 7. Hardware validation gates (minimal, in order)

Precondition: keep the golden v0.0.1 card; confirm a COM9 root login works
before the new card goes in.

1. Boot on serial. Expect `Starting radiod (mock, EU868, 2 dBm): OK` and
   `Starting telnetd: OK`. Read the IP.
2. `ssh root@<ip>` with the empty password must be refused. `telnet <ip>`
   must not connect from the PC; `telnet 127.0.0.1` on serial must.
3. `passwd` on serial, then SSH with the password must succeed; one scp or
   deploy.sh dry run confirms the remote workflow.
4. `pos radio status` shows tx power 2, backend mock. Raise to 10, restart
   S60radiod, confirm 2 again.
5. `RADIOD_TX_POWER_DBM=15` in `/etc/default/radiod`, restart: exit 2 in
   the radiod log, crashloop marker after the retries. Remove, restart,
   recovered.
6. `RADIOD_BACKEND=sx1262`, restart: `radio info` shows sx1262 at 2 dBm,
   state rx. No transmit needed.
7. `pos-hwcheck --lora` with sx1262 active: exit 3, inventory written.
   Stop radiod, run again: `14 24`, exit 0, `ps` shows no gpioset. Start
   radiod on sx1262 again and confirm it initialises.
8. `killall radiod` under the running shell: shell pid unchanged, Radio app
   shows the service gone and back. Then the Stage 3 crash loop from the
   post-bring-up review.
9. One SIGSEGV of radiod: crash file ends in `-<pid>.txt`; supervise log
   shows a sane run time after NTP.
10. Reboot: password persisted, steps 1 and 4 still hold.

Steps 2 and 3 must pass before the card leaves the bench with serial
attached. Step 7 is the only one with a plausible false negative (reset
line release, ASSUMED pull-up).
