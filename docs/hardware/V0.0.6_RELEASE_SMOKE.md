# PocketOS v0.0.6: release image and hardware smoke test

v0.0.6 is diagnostic hardening of `pos-hwcheck --lora` only (README, entry
0.0.6); radiod, RadioLib, the shell and the apps are the v0.0.5 binaries
rebuilt from the same source, and the M7 register read was VERIFIED on unit
A with the deployed 27be0f8 files (V0.0.6_M7_BENCH.md). This sheet is the
shortest smoke test that shows the release image boots and behaves as
v0.0.5 did, plus the one new tool. **No transmission at any step.** Every
command runs as root on the device (serial or SSH).

## Flash (Windows, elevated)

The v0.0.5 gated writer pattern, copied to `out/k230-v0.0.6/` with the
v0.0.6 image path, size and SHA-256: identity gates (USB, removable, exact
card size, not the system disk), source-hash gate, volume lock and dismount,
throttled resumable raw write, read-back hash, then a byte compare of the
written range where the only allowed difference is bytes 440..443 (the MBR
disk identifier Windows assigns). Run `ident-card.ps1` first: the golden,
v0.0.3, v0.0.4 and v0.0.5 cards are not to be overwritten.

```powershell
powershell -ExecutionPolicy Bypass -File C:\K230\out\k230-v0.0.6\ident-card.ps1
powershell -ExecutionPolicy Bypass -File C:\K230\out\k230-v0.0.6\flash-and-verify-v0.0.6.ps1
```

Expected last line: `VERDICT: FLASH PASS - READY FOR K230`.

## Smoke test on unit A

Boot with COM9 open (115200 8N1) or SSH once the network is up. On a fresh
card hand the panel over as in the v0.0.3 sheet (`ENABLE=0` in
`/etc/default/k230_phone_ui`, `ENABLE=1` in `/etc/default/pocketos-shell`,
reboot) and reinstall the bench SSH key if SSH is wanted.

- [ ] **S1 boot and identity.** Serial shows `Starting radiod (mock, EU868,
      2 dBm): OK` and `Starting pocketos-shell: OK`; the shell is on the
      panel.
      ```
      cat /etc/pocketos-release; pos version; pos radio info | head -4; ps | grep -E '[r]adiod|[p]ocketos-shell'
      ```
      Expected: `0.0.6`; `pos 0.0.6 (build 76b43f1)`; chip and backend
      `mock`; radiod and the shell running under pos-supervise.
- [ ] **S2 the new tool is in the image.**
      ```
      sha256sum /usr/bin/pos-hwcheck /usr/bin/pos-spixfer; pos-spixfer; echo "usage exit $?"
      ```
      Expected: the two SHA-256 values from the "Changed in the rootfs"
      row, a usage line, `usage exit 2`.
- [ ] **S3 M7 on the release image** (radiod on mock, no transmit).
      ```
      pos-hwcheck --lora /root/hwcheck-v006-release > /root/hwcheck-v006-release.txt 2>&1; echo "exit $?"; sed -n '/=== LoRa/,$p' /root/hwcheck-v006-release.txt; ps | grep '[g]pioset' || echo "no gpioset"
      ```
      Expected: `SX126x ready N ms after reset ... held over two polls`;
      `6-byte window:  aa aa aa aa 14 24` (or `a2 ...`: the status byte is
      chip state, the sync word is the check); `sync word registers read
      14 24 ... (VERIFIED)`; the spi-pipe comparison line with the same
      bytes; `no gpioset process left behind`; `exit 0`; `no gpioset`.
      If the read is `24 b4` again, record both windows and the status
      byte, exit 5 is the expected verdict, and the release is not blocked
      (KNOWN_ISSUES, closed as understood): it is the trigger for the
      investigation that v0.0.6 deliberately does not start.
- [ ] **S4 radio under radiod, receive only.**
      ```
      printf 'RADIOD_BACKEND=sx1262\n' > /etc/default/radiod; /etc/init.d/S60radiod restart; sleep 3; pos radio status | grep -E 'state|tx_power'; pos radio rssi; rm -f /etc/default/radiod; /etc/init.d/S60radiod restart
      ```
      Expected: `(sx1262, EU868, 2 dBm): OK`, state `rx`, `tx_power_dbm` 2,
      a plausible RSSI (about -70 to -110 dBm), then `(mock, EU868, 2 dBm):
      OK` again.
- [ ] **S5 shell and apps, one reboot.** Open Fleet and Radar from the
      panel, back out, `reboot`; after the reboot S1 again and
      ```
      ls -la /var/lib/pocketos/ 2>/dev/null || ls -la /root/.pocketos 2>/dev/null; ls /run/pocketos/*.crashloop 2>/dev/null || echo "no crash-loop marker"
      ```
      Expected: the shell back on the panel, no crash-loop marker.
