# PocketOS v0.0.8: release image and hardware acceptance (2026-09-11)

The four-section acceptance run for the v0.0.8 release candidate, frozen at
`03851f5`, carried out on unit A from a freshly flashed card. v0.0.8 is the
text-input line (M3 key stream, M4 touch keyboard, M5 PocketNotes),
PocketClock with the shell-owned system alert of DS §18 (Amendment B), and
the six P1 fixes of the cold review. Until this run PocketClock had never been
on hardware, and Notes had only run as a bench deployment of `0b16f0e`
(POCKETNOTES_SMOKE_2026-09-10.md).

**Verdict: PASS.** All four sections passed. Two STOPs were raised along the
way and both were resolved with the product owner as operator input, not
software; each is described where it happened. Nothing was rebuilt after the
freeze, so the image this sheet validates is `BUILD_ID=03851f5`. No
transmission at any step; radiod kept the image's default mock backend. The
keyboard base was attached throughout; PocketOS does not use it.

Remote results are VERIFIED on unit A over SSH, with strict host-key checking
against the key read off the serial console. What the panel showed is the
operator's observation. Times are board time, which is UTC.

Every alert returned to exactly the screen it covered: the shell log shows no
app change during any of them (DS §18.5). The three services kept their pids
with 0 restarts, and every check found 0 ERROR and 0 WARN lines and no `.tmp`
file.

**STOP 1, operator input.** A was reported as Daily, but `clock.conf` stored
repeat `0`, Once. The row read `Once  test æøå`, so the screen agreed with the
file: the operator had not changed Repeat. The product owner ruled it operator
input, not a defect; the lower-case `t` is likewise what was typed.

**The run differed from the sheet in three places**, none of them a defect:

- A was Once rather than Daily (above), so it was stopped rather than snoozed,
  and a Daily alarm was not exercised.
- B was added during 15:42 for 15:42, because Minute +5 had not been applied.
  An alarm added for a minute that has already begun counts as passed today
  and arms for the next day (POCKETCLOCK.md, "Firing exactly once"), so B
  correctly did not ring; its row read `15:42` Once On, matching
  `alarm 1 15 42 0`. C took over the launcher step, with Snooze instead of
  Stop, and C's return took over the snooze-over-Notes step planned for A.
- The timer was 2:00 rather than 1:00.

Found here:

- **The board runs UTC.** The image configures no time zone; the operator's
  local clock was two hours ahead of the face. (KNOWN_ISSUES)
- **The minute stepper wraps within the hour.** Adding C from 15:58, Minute +5
  gave 15:03 - of the same hour, and already past. The operator added an hour.
  (KNOWN_ISSUES)
- **The label's keyboard Done does nothing**, as the preflight had found; Add
  was tapped directly. (KNOWN_ISSUES)
- **Linux refuses a wall time earlier than the uptime.** The sheet's
  `date -u -s '1970-01-01 00:05:00'` failed with `Invalid argument`;
  `1970-01-02` works. (POCKETCLOCK.md)

## 3. PocketNotes, and persistence

The store was seeded over SSH with Notes closed: Seed 01 to Seed 20, and
**Prose**, 1,980 bytes - the line `Prose` and 47 repetitions of `the quick
brown fox jumps over a lazy dog `, just under the editor's 2000-character
cap, so it opens editable. Their checksums were kept to prove later that
opening a note does not rewrite it.

| Check | Result | Evidence |
| --- | --- | --- |
| 21 notes, the oldest and New note reachable | PASS | operator: Prose at the top, New note visible without scrolling, the list scrolled by finger to Seed 01, opened, Done. Before `03851f5` the list clipped from sixteen notes |
| A new note with æ ø å | PASS | remote: `note-00000022.txt`, 18 bytes, `Test æøå` / `line 2`, `c3 a6 c3 b8 c3 a5`, 0644 root in a 0755 directory |
| Leaving by the shell's Back, without Done | PASS | a controlled repeat: ` back` typed, Back pressed; Notes closed at 16:27:11 and the file became 28 bytes ending `line 2 edit back` |
| A note nobody changed is not written | PASS | the same note reopened and left with Done stayed at 28 bytes and 16:27; Seed 01 and Prose, opened and left, kept their checksums |
| Delete, Cancel, Delete | PASS | operator: Cancel gave back the editor and the keyboard; remote: only `note-00000002.txt` removed, the other twenty seeded notes unchanged |
| Opening a near-limit note | PASS, **under 4 s** | operator count from tap to editor, panel responsive; the gate was 5 s |
| The alert over the editor | PASS | section 2 |

The 4 s is an operator count, not an instrument reading. The slow path is
known - the editor takes the text one character at a time under its cap
(KNOWN_ISSUES) - and its worst case, two-byte text with no spaces, was not
measured on the board.

Two apparent misses were procedure. A report of "done" arrived before Done had
been tapped, so the note was not on disk yet; and one Back-only attempt never
reached the board. The controlled repeat above settled the Back save.
