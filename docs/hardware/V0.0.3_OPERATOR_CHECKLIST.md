# PocketOS v0.0.3: operator checklist

v0.0.3 is a platform-only release. No application source changed, the
filesystem layout is unchanged, and nothing about the radio's on-air behaviour
moved. So this sheet is not a repeat of the v0.0.2 sheet: it checks the nine
things v0.0.3 actually changed, one independent PASS/FAIL each, and then a
short regression block whose whole purpose is to show that everything else
behaves exactly as it did.

Rules for this session:

- **No transmission at any step.** M7 brings the SX1262 up, so an antenna must
  be fitted before that block, but nothing is ever sent.
- Run in the order given. The blocks are independent: a failure in one is
  recorded and the next is still run, unless the failure makes the next
  impossible (noted where that applies).
- Every command runs as root on the device unless marked **PC**.
- Image, hashes and provenance: `docs/hardware/V0.0.3_BUILD_REPORT.md`.

Each block ends with a single line to mark. Write the observed value, not just
the verdict; a PASS with no number recorded is not evidence.

## M1 — the image is a function of a commit

The v0.0.3 build takes the package source and the rootfs overlay from
`git archive`, so the file modes in the image come from git rather than from
the build host's filesystem. Before v0.0.3 the init scripts were committed
non-executable and only ran because the build host reported every file as
0777. This block is the check that the fix reached the image.

- [ ] After the reboot above, rcS shows **both** services starting:
      `Starting radiod (mock, EU868, 2 dBm): OK` and
      `Starting pocketos-shell: OK`. The launcher line reads
      `disabled (/etc/default/k230_phone_ui)`.
- [ ] ```
      ls -l /etc/init.d/S60radiod /etc/init.d/S90pocketos-shell
      ```
      Both `-rwxr-xr-x` (0755). **FAIL on `-rw-r--r--`**, which means the
      services could not have started; **FAIL on `-rwxrwxrwx`**, which means
      host filesystem modes are still leaking into the image.
- [ ] ```
      ls -l /etc/default/telnet /etc/pocketos/settings.conf
      ```
      Both `-rw-r--r--`. Data files must not be executable.

**M1: PASS / FAIL** — observed modes: S60 ______ S90 ______ telnet ______

## M4 — the filesystem roots moved into one module, and nowhere else

`core/pocketpaths` now owns the four roots. The values are unchanged, and the
first check is that they are unchanged; the second is the one behaviour that
did change, and it is a fix.

- [ ] ```
      ls -d /run/pocketos /etc/pocketos /var/lib/pocketos /var/lib/pocketos/log
      ```
      All four present. **FAIL on any path that moved.**
- [ ] Sockets, pid files and settings are where they were:
      ```
      ls /run/pocketos/ /etc/pocketos/
      ```
      `radiod.sock`, `shell.sock`, `radiod.pid`, `pocketos-shell.pid`;
      `settings.conf`.
- [ ] A missing log directory is recreated instead of silently disabling
      logging (before v0.0.3 the log was lost for the life of the process).
      Tested in isolation with a three-level missing path, because
      `S60radiod` itself runs `mkdir -p` on the real log directory and would
      mask the daemon's own recreation:
      ```
      rm -rf /tmp/m4
      POCKETOS_LOG_DIR=/tmp/m4/state/deep/log /usr/sbin/radiod --backend mock --socket-name m4test &
      sleep 1; kill $!
      ls -l /tmp/m4/state/deep/log/; head -1 /tmp/m4/state/deep/log/radiod.log
      ```
      `radiod.log` exists under the created path and its first line is
      `start version=<version> build=<id> pid=<n>`. Do not delete
      `/var/lib/pocketos/log` on a running system: the shell keeps its old
      log inode open and `shell.log` disappears until the next shell start
      (unit A, 2026-09-08).

**M4: PASS / FAIL** — nested path created and logged: YES / NO

## M5 — a wedged service no longer freezes the shell

The single most important check on this sheet. radiod is stopped with SIGSTOP:
alive, holding its socket, answering nothing. Before v0.0.3 the shell blocked
in a read forever and stopped servicing its own socket too, while the
supervisor saw two healthy processes.

Unit A, 2026-09-08, v0.0.3: the status poll was bounded and the chip went
`--`, but with the Radio app open its once-a-second tick called radiod
without a deadline and froze the panel, touch and the shell's own socket
until SIGCONT. v0.0.4 bounds every app tick with the same 200 ms, so from
v0.0.4 this block is run **with the Radio app open** (that is the case that
failed) and passes only if the panel stays alive throughout.

- [ ] Open the Radio app on the panel. Note the time, then wedge radiod:
      ```
      kill -STOP $(cat /run/pocketos/radiod.pid)
      ```
- [ ] **Watch the panel for 30 s.** The clock keeps advancing. The status-bar
      chip changes to `--` and the Radio app's rows read unavailable. Touch
      still works: go back to the launcher, open Fleet, go back, reopen Radio.
      **FAIL if the panel freezes or touch stops responding.**
- [ ] `pos shell info` answers (from serial or SSH) while radiod is still
      stopped.
- [ ] ```
      grep -E 'poll failed|answering again' /var/lib/pocketos/log/shell.log
      ```
      One line naming `timed out after 200 ms`, logged once, not once a second.
- [ ] Release it and watch the chip return:
      ```
      kill -CONT $(cat /run/pocketos/radiod.pid)
      ```
      Chip returns to `RX` within about 2 s; the log gains one
      `radiod is answering again`.

**M5: PASS / FAIL** — panel responsive while wedged: YES / NO — chip `--`
then `RX`: YES / NO

## M6 — the shell stops cleanly

Unit A, 2026-09-08, v0.0.3: `stopping on signal` was logged and the socket
removed, yet the stop read `OK (forced)`. The supervisor left as soon as it
had signalled the shell, before the shell had finished leaving, and the init
script SIGKILLed a shell that was already on its way out. v0.0.4's
supervisor stays until its child is gone; a plain `OK` is the pass.

- [ ] ```
      /etc/init.d/S90pocketos-shell stop
      ls /run/pocketos/
      tail -3 /var/lib/pocketos/log/shell.log
      ```
      `shell.sock` is **gone**, the log ends with `stopping on signal`, and the
      stop line reads `OK`, not `OK (forced)`.
- [ ] `/etc/init.d/S90pocketos-shell start` → panel returns, `pos shell info`
      answers.

**M6: PASS / FAIL** — socket removed: YES / NO — stop reported: OK / forced

## M2 — stop confirms before it returns

`restart` used to be stop, sleep 1, start, with a stop that returned whether or
not anything had gone. On a fast host that left two supervisors.

- [ ] The image's BusyBox has no `pgrep`; count with `pidof`:
      ```
      for i in 1 2 3; do /etc/init.d/S60radiod restart; sleep 1; echo "radiod count: $(pidof radiod | wc -w)"; done
      ```
      Exactly `1` all three times. **FAIL on `2`.**
- [ ] Each restart prints `Stopping radiod: OK`, not `OK (forced)`. A forced
      stop is not a failure of this block, but record it: it means something
      ignored SIGTERM.
- [ ] `pos radio status` answers after the third restart.

## M7 — radiod owns the SPI device exclusively

**Antenna required.** This block initialises the SX1262, so an antenna must be
fitted to MMCX1 first. **Nothing is transmitted.** If no antenna is available,
skip this block and record it as NOT RUN rather than guessing.

- [ ] Antenna confirmed fitted to MMCX1 (the SX1262 port). Operator initials: ____
- [ ] ```
      printf 'RADIOD_BACKEND=sx1262\n' > /etc/default/radiod
      /etc/init.d/S60radiod restart
      ```
      Line reads `(sx1262, EU868, 2 dBm): OK`; `pos radio info` → backend
      `sx1262`; `pos radio status` → state `rx`.
- [ ] A second radiod on the same device must be refused, not allowed to share
      the bus:
      ```
      /usr/sbin/radiod --backend sx1262 --socket-name spitest
      ```
      Fails and prints `already in use by another process`.
      **FAIL if it starts.**
- [ ] The first radiod is unharmed: `pos radio status` still answers, state
      `rx`, and `pos radio stats` shows no new errors.
- [ ] hwcheck refuses while radiod owns the radio:
      ```
      pos-hwcheck --lora
      ```
      → `REFUSED`, exit 3, and the read-only inventory is still produced.
- [ ] hwcheck succeeds once radiod is out of the way:
      ```
      /etc/init.d/S60radiod stop
      pos-hwcheck --lora; echo "exit $?"
      ps | grep '[g]pioset' || echo "no gpioset"
      ```
      → the report shows `reset: GPIO5 driven low for 20 ms, then driven
      high and held`, `BUSY (GPIO19) inactive within N ms of reset`, the
      register line ending `14 24`, a GetStatus byte pair, exit `0`, and
      no `gpioset`. Unit A, 2026-09-08, v0.0.3: the probe released RST
      instead of driving it high, BUSY stayed active and the read returned
      `ff`; v0.0.4 follows radiod's own reset sequence.
- [ ] Put it back:
      ```
      rm -f /etc/default/radiod
      /etc/init.d/S60radiod restart
      ```
      → `(mock, EU868, 2 dBm): OK`.

**M7: PASS / FAIL / NOT RUN** — second instance refused: YES / NO — hwcheck
refused then succeeded: YES / NO

## REGRESSION — everything v0.0.3 did not change

v0.0.3 changed no application source. Fleet and Radar are byte-for-byte what
v0.0.2 shipped, so anything here that differs is a platform regression, not an
app change.

- [ ] **Fleet**: open it. If a save from an earlier session exists, Resume is
      offered and restores that match. Play one turn, leave the app, reopen:
      the same state is there. Reboot, reopen: still there.
- [ ] **Radar**: open it. BEST shows the previously stored value. Play one run
      to completion; if it beats BEST the record updates. Reboot, reopen: the
      record persists.
- [ ] **PocketTimber is not in this image** and must not appear in the
      launcher. It lives on `pockettimber-engine` and has never been part of
      this line. Seeing it would mean the wrong image was flashed.
- [ ] No visual or timing difference from v0.0.2 in either app: no clipping,
      no font changes, no new stutter.
- [ ] ```
      ls /var/lib/pocketos/
      ```
      `fleet/`, `radar/`, `log/` and nothing unexpected. No `timber/`.

**REGRESSION: PASS / FAIL** — Fleet ______ Radar ______ Timber absent: YES / NO
