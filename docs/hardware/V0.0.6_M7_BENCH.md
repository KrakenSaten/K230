# PocketOS v0.0.6: M7 register-read bench on unit A (2026-09-09)

The question left open by the v0.0.5 retest: `pos-hwcheck --lora` read the
SX1262 sync-word registers 0x0740/0x0741 as `24 b4` (status `a2`) where
radiod reads `14 24`, with the same MOSI bytes (`1D 07 40 00 00 00`, data at
returned offset 4). Commit `27be0f8` moved the probe's SPI traffic from
spi-pipe to `pos-spixfer`, a helper that performs the transaction exactly as
radiod's HAL does, and this bench compares the two transports on one chip
state. **No transmission at any step.** Every command ran as root over SSH
(key `pocketos-bench-2026-09-08`); no image was flashed.

## Conclusion

Outcome B of the three planned: both transports return `14 24`. The
transport is not the cause of the `24 b4` readings, and the frame never was
(spi-pipe 1.0.2 also issues a single `SPI_IOC_MESSAGE(1)` per block; the
real differences to radiod were the clock, the per-transfer `speed_hz` and
`bits_per_word`, and the `O_RDONLY` open, none of which changed the bytes).
Every run that read `14 24` (bringup 2026-09-07, this bench) had the chip's
status byte at `aa` (command status 5); both runs that read `24 b4`
(2026-09-08, 2026-09-09 morning) had `a2` (command status 1). The value is
chip-state dependent. Per the owner's decision it is not investigated
further unless it recurs on hardware; `27be0f8` stays in v0.0.6 as probe
hardening (radiod's transaction parameters, no spi-pipe dependency, loud
failure with both transports' bytes as evidence), not as a root-cause fix.
