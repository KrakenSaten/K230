# PocketOS v0.0.3: image build report

Build-only step. Nothing was flashed, no card was written, the K230 was not
touched, COM9 was not opened, nothing was transmitted, and nothing was merged
or pushed. The golden v0.0.1 image and the v0.0.2 candidate were verified
unchanged before and after.

## Verdict

**READY TO FLASH WITH PRECAUTIONS.**

The image builds clean from the exact source HEAD, and every offline check for
M1 to M9 passes against the image itself rather than against the source. The
precautions are in §10 and are not incidental: this image has never run, the
root account still ships with no password, and the vendor's Wi-Fi credentials
are still in the U-Boot environment.

One finding from this session is material to the flashing decision and is in
§8: **the v0.0.2 candidate image cannot start PocketOS at boot.** Its two init
scripts are mode 0644 in the image and BusyBox `rcS` executes them directly.
v0.0.3 is the first image in which that is fixed.

## 8. Finding: the v0.0.2 candidate cannot start PocketOS at boot

Confirmed on the artefact, not inferred:

- `/etc/init.d/rcS` in the image runs `$i start` for every `/etc/init.d/S??*`
  that does not end in `.sh`. Both PocketOS scripts qualify, so both must be
  executable.
- In `out/k230-v0.0.2/sysimage-sdcard.img`, `S60radiod` and
  `S90pocketos-shell` are **mode 0644**.
- In `out/k230-v0.0.3/sysimage-sdcard.img`, both are **0755**.
- The vendor's own `S99zz_k230_phone_ui` is 0755 in both, because it comes
  from the vendor tree rather than from our git.

So a v0.0.2 card would boot into the vendor launcher with neither radiod nor
the shell running, and `rcS` would report permission denied for both. The
golden v0.0.1 image was built from the Windows mount, where every file reports
as executable, which is why it did start its services on the bench
(`BRINGUP_SESSION_2026-09-07.md`); v0.0.2 was built from a tree where git's
modes applied, and git held 0644. This is exactly the defect the architecture
review recorded as D2, and it is why v0.0.3 committed the executable bits and
switched both syncs to `git archive`.

**Recommendation, not a decision:** flash v0.0.3 rather than v0.0.2. v0.0.3
contains every v0.0.2 fix, and v0.0.2 cannot demonstrate them. The open
question recorded in `ROADMAP.md` is answered by evidence in this direction.

## 9. What this build does not establish

Everything in §6 is a property of the image, not of a running device. Nothing
here has executed on hardware. Specifically untested:

- Every M1 to M9 behaviour end to end. The image contains the code and the
  right file modes; the checklist
  (`docs/hardware/V0.0.3_OPERATOR_CHECKLIST.md`) is what turns that into
  evidence.
- **M7 has no host coverage at all.** The SPI `flock` needs `ENABLE_SX1262`
  and a real spidev, so neither the lock nor the refusal path has run
  anywhere. It is six lines and is the cleanest single item to drop if the
  bench dislikes it.
- The bounded init-script stop escalating to SIGKILL, which has only ever run
  against stub daemons on the host.
- Whether `pocketos_mkdir_p` recreating a deleted log directory behaves the
  same on the device's ext4 as on the host.

## 10. Precautions for the flashing session

1. Write to a **third** card. The golden v0.0.1 card and the v0.0.2 card stay
   out of the reader.
2. Verify the raw SHA-256 in §5 before writing, and read back after.
3. Hold COM9 open through first boot. SSH refuses an empty password, so serial
   is the only way in until `passwd` has been run.
4. **Root still ships with no password.** Set one on the serial console before
   the board goes on any shared network. Unchanged from v0.0.2; not fixed here.
5. **The vendor's `wlanssid`/`wlanpass` are still in the U-Boot environment**
   (2 strings in MiB 1, identical in v0.0.2 and v0.0.3). Known issue F2,
   carried over, not introduced. `wlan0` is not `auto`, so it stays dormant.
6. M7 initialises the SX1262, so an antenna must be fitted to MMCX1 before that
   block. **Nothing is transmitted at any point in the checklist.**
7. If a step fails, record it and continue: the blocks are independent.
