# Doors 0.3.8 candidate: fresh-card hardware smoke test

**Build under test: `0.3.8`, `BUILD_ID=bc889b0d`** (release/v0.3.8 commit `bc889b0d`).
Check it first: System > About, or `cat /etc/doors-release`.

Image: `C:\k230\out\doors-0.3.8-bc889b0\sysimage-sdcard.img`, 763,363,328
bytes, sha256 `61446a8bfcf2f5920d1d9702d81ce4a40819a30140bf8d95f5d7fc0d2c4068ba`. Compressed
release file `C:\k230\out\v0.3.8-release\doors-0.3.8-tdisplay-k230-bc889b0d.img.gz`,
sha256 `47a4dfa94d24bff5ef77070b0c1112aa2426a7dcd56742edd8fc35b9ea1ec165`.

The smallest check that this release image boots and carries what was merged
since 0.3.7. It is not a feature acceptance: gameplay, camera and RF were
validated on unit B before their PRs merged (docs/releases/v0.3.8.md,
"Validation") and are not repeated. What changes from v0.3.7 and is checked
here: the first release image built on this PC (every vendor package and
the kernel rebuilt from a clean SDK output; same file set as 0.3.7 plus
`/usr/bin/pos-audio-effects`), Relay Nine and its effects helper, DeskBuddy
camera presence and the Guard visit-sound switch, RIFT's route builder and
composer changes, and the Neon theme. NinjaOne is not in this image.

**No radio transmission is authorised.** Do not set up RIFT or turn the
radio on; a fresh card does not start meshcored by itself. Use a spare
card; the units' own cards are not touched.

## 1. Flash (PC, owner)

`tools/flash-devcard.ps1` is not on this PC, so the card is written with a
standard tool (Raspberry Pi Imager "Use custom", or balenaEtcher) from either
file above; both tools read the `.img.gz` directly and verify the write.
Write only to the card the owner has identified as the spare.
