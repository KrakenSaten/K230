# Doors 0.3.6 candidate: fresh-card hardware test

**Build under test: `0.3.6`, `BUILD_ID=<image commit>`** - filled in when the
candidate image is built (release/v0.3.6). Check it first: System > About, or
`cat /etc/doors-release`.

Image: `C:\K230\out\doors-0.3.6-<id>\sysimage-sdcard.img`, sha256 from that
directory's BUILD_INFO.txt. Not built yet: the R0 detector file is not on the
build PC (docs/releases/v0.3.6.md, "Before publishing").

What is established before hardware, once the image exists: the image gate
(`verify_image.sh`) and the release inspection check R0 at
`/usr/share/doors/vision/det-r0-traffic6-yolox-tiny-416.kmodel` with sha256
`94a20ac0…d268`, and that `yolov8n.kmodel`, the upstream YOLOX-Tiny and every
other kmodel are absent. Whether it boots and works is what this sheet is for.

**Coordinate every step with the owner. Nothing here is done without the
owner's go.** Use a spare card. Unit A's own card, and the models installed
on it for testing, are not touched.

## 1. Flash (PC, owner present)

A **spare** microSD card (16 GB or larger) as the only removable disk:

```powershell
powershell -ExecutionPolicy Bypass -File C:\K230\tools\flash-devcard.ps1 -Image C:\K230\out\doors-0.3.6-<id>\sysimage-sdcard.img -Sha256 <raw image sha256> -DryRun
```

If the dry run names the spare card, run it again without `-DryRun` and
record the `RESULT:` line.

## 2. Checks (unit B with its own card taken out and kept)

Mark each PASS / FAIL with a note. Antenna on MMCX1 before any radio step.

| # | Check | Expect |
| --- | --- | --- |
| 2.1 | Cold boot from the fresh card | straight into Doors (lock screen or launcher); no LILYGO menu; no boot loop |
| 2.2 | Identity | System > About and `/etc/doors-release`: `0.3.6`, the build id above |
| 2.3 | Navigation | touch; keyboard base; F1 Home; Power key (short: screen, 1 s: power menu); BOOT key (short: Back, 1 s: Home) |
| 2.4 | Wi-Fi | Settings > Wi-Fi: join a network; connected; Browser loads a page |
| 2.5 | Vision opens on R0 | Vision opens in DETECT; while it starts, "Opening the camera and the R0 · Beta detector"; then the detector button reads **R0 · Beta**, greyed (no other detector to choose), and DETECT's numbers start with "R0 · Beta". Note the KPU ms and fps shown |
| 2.6 | R0 detects | a person in view is boxed as person; if a car, truck, bus, motorcycle or bicycle can be shown (street, picture on a screen), note what is boxed and what is missed. Misses are expected (beta); record them, do not fail the step on them |
| 2.7 | TRACK and TRAFFIC | both offered in the picker; TRACK shows ids and the line; TRAFFIC shows its per-class line (car truck bus moto bike person); the R0 · Beta button is the last one in both, legible in the orientation used |
| 2.8 | Model-free modes | COLOR, EDGE and LINE TRACE run. Close Vision once; do not open and close repeatedly (known camera lock-up) |
| 2.9 | DeskBuddy | "NO VISION YET" (it does not use R0; same as 0.3.5); clock works |
| 2.10 | Normal reboot | restart from the power menu: Doors again; Wi-Fi reconnects; Vision opens on R0 · Beta again without a message |

Optional if time allows: Camera preview and a photo; RIFT setup from
Controls (as in V0.3.5_FRESH_CARD_TEST.md 2.5) with the antenna confirmed.

Useful lines from a shell (Terminal or SSH), read-only:

```sh
cat /etc/doors-release
sha256sum /usr/share/doors/vision/*.kmodel
grep 'vision: detector' /var/lib/pocketos/log/shell.log | tail -5
```

Expected: one kmodel, `94a20ac0…d268  det-r0-traffic6-yolox-tiny-416.kmodel`;
the log says `detector R0 · Beta in force`.

## 3. Afterwards

Put unit B's own card back. Nothing on unit B's own card is touched by this
test. The spare card keeps its own identity; reflash or keep it as a test
card.
