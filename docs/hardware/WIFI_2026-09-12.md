# Wi-Fi on the T-Display K230

Recorded 2026-09-12 from a read-only study of the schematic, the pinned
kernel and Buildroot build trees (`k230_pocketos_defconfig`, the tree unit
A's image is built from), the rtl8189fs driver source, the vendor launcher and
the unit A bench records. No radio was used and no board was contacted.

Classes: VERIFIED (unit A record), DOCUMENTED (schematic, source, config),
ASSUMED (inference), UNKNOWN.

Paths: `BT` = `output/k230_pocketos_defconfig` in the WSL SDK tree; `DRV` =
`BT/build/rtl8189fs-94cc959d…`; `SCH` = the V1.0 schematic.

## Hardware and driver

| Fact | Value | Evidence |
| --- | --- | --- |
| Chip | RTL8189FTV family (schematic part U14 "RTL8821/RTL8189"); SDIO id `0x024c:0xf179` bound to `rtl8189fs` | VERIFIED (driver, id), DOCUMENTED (part) |
| Bus | SDIO on `mmc_sd0` = `sdhci0@91580000`, 4-bit, `no-1-8-v`, `cap-sdio-irq`, `keep-power-in-suspend`; no `mmc-pwrseq`; card detected at 2.17 s | DOCUMENTED, VERIFIED (detection) |
| Power | GPIO45 `IO45_WIFI_EN` enables U24, an RT9080-33 regulator whose output feeds the chip. The net has a 100 kΩ pull-down; the pull-up is not fitted. U-Boot configures the pad as GPIO with pull-up and nothing in Linux claims line 45. So the rail is on only because the pad pull-up wins | DOCUMENTED; the "pull-up wins" part ASSUMED |
| Reset | WL_REG_ON → K230 `MMC0_RST_N` with a 10 kΩ pull-up; host-wake unconnected | DOCUMENTED |
| Driver | out-of-tree `8189fs.ko` (jwrdegoede rtl8189ES_linux, v5.7.9), loaded by the generated `S40k230_pocketos_defconfig` with a plain `modprobe 8189fs` and no parameters | VERIFIED (loaded), DOCUMENTED (script) |
| Interfaces | `wlan0` (station, burned-in MAC) and `wlan1` (locally administered twin from `CONFIG_CONCURRENT_MODE`, which is unconditional in the driver Makefile) | VERIFIED (both present), DOCUMENTED (cause) |
| Stack | the driver is cfg80211/nl80211 (`CONFIG_IOCTL_CFG80211`), implements `.connect` and `.scan` itself (no `.auth`/`.assoc`); kernel `CFG80211=y`, `CFG80211_WEXT=y`, `RFKILL` unset | DOCUMENTED |
| Firmware | embedded in the module (`CONFIG_EMBEDDED_FWIMG`); nothing to load from `/lib/firmware`; no `regulatory.db` (the kernel says so in dmesg) | DOCUMENTED, VERIFIED (regdb missing) |
| Power save | driver defaults: IPS on, LPS max; `CFG80211_DEFAULT_PS=y` | DOCUMENTED |
| **WPA3-SAE** | **not possible with this driver build**: `CONFIG_80211W=n` (no management frame protection), no external-auth or SAE offload. WPA2-PSK works; WPA2/WPA3 transition networks can be joined as WPA2 | DOCUMENTED |
| Regulatory | driver's own channel plan (`rtw_channel_plan=0xFF`, no country code); whether a supplicant `country=` would reach it is unknown | DOCUMENTED, UNKNOWN |
| Coexistence | separate regulators for Wi-Fi (U24) and LoRa (U27), separate antennas (Wi-Fi chip antenna ANT1; LoRa on MMCX1). 868 MHz harmonics fall outside 2.4 GHz. LoRa receiver desense while Wi-Fi transmits is unmeasured | DOCUMENTED, ASSUMED, UNKNOWN |

**Vendor network scripts.** `S40network` runs `ifup eth0` when the USB
Ethernet adapter is present, otherwise **`ifup wlan0`**, then `ifup -a`. The
vendor `/etc/network/interfaces` has a `wlan0` stanza that builds
`/tmp/wpa_supplicant.conf` from the U-Boot variables `wlanssid`/`wlanpass`
(`fw_printenv`) and starts `wpa_supplicant -B` on wlan0. The image has no
`/etc/fw_env.config`, so that probably fails (ASSUMED). If it ever succeeds,
netd finds a wpa_supplicant it did not start and reports
`unavailable`/`interface_busy` rather than fighting it. The stanza is also the
consumer of review finding F2 (vendor credentials in the U-Boot environment);
removing it at apply time is recommended but was not done here, because it
changes the image-build script.

**Vendor launcher** (mechanism only): `iwlist wlan0 scan`, a generated shell
script that runs `wpa_supplicant -B` and `udhcpc -q -n` (which exits after the
first lease and never renews), plaintext profiles in
`/root/app/k230_phone_ui/wifi_profiles.conf`. It is off whenever the PocketOS
shell owns the panel. DOCUMENTED.

## What PocketOS implements

`netd` (`services/netd`, `/etc/init.d/S55netd`), API `docs/api/network.md`,
credential rules `docs/decisions/ADR-003-wifi-credentials.md`, CLI `pos wifi`,
and the Wi-Fi section of Settings. In short: one supplicant netd starts with a
network-less config and drives over its control socket, one foreground
`udhcpc -f -R` per association, WPA2-Personal (and transition networks as
WPA2), open networks only when explicitly allowed, hidden networks when named
with their security, the joined networks in a root-only store, reconnect
after reboot, everything asynchronous. Host-tested only.

## Physical validation for unit A (not done)

Needs: unit A on the bench with Ethernet, a 2.4 GHz WPA2-Personal test
network whose passphrase the operator knows, and a second phone as the access
point if the office network is not suitable. No LoRa transmit is involved.

0. Get the branch onto unit A. Either deploy userspace
   (`platforms/k230/scripts/deploy.sh <ip> ~/work/t-display-k230`; the stop
   loop skips an S55netd the card does not have yet, and deploy.sh refuses to
   start unless S55netd is in the target tree, which needs a full
   `build_image.sh`, not only `pocketos-rebuild`), or flash a dev image. A dev
   image was built overnight from `3d4a6e7` (not a release, not flashed):
   WSL `~/work/found-image-3d4a6e7/sysimage-sdcard.img`, 763,363,328 bytes,
   SHA-256 `95ed2b2e7de184c40480915e159e08d9d44b72749c92583e3be7b95e8a9fb55e`,
   image gate PASS, `/etc/pocketos-release` BUILD_ID=3d4a6e7, S55netd 0755
   root; the SDK tree at `~/work/t-display-k230` carries that apply and full
   build, so deploy.sh works from it as is. `pos version` shows the build.
1. Read-only inventory, record everything:
   ```
   ls /sys/class/net; cat /sys/class/net/wlan0/address
   ls -d /sys/class/net/wlan0/wireless /sys/class/net/wlan0/phy80211
   cat /sys/class/net/wlan0/phy80211/name /sys/class/net/wlan1/phy80211/name
   grep -H . /sys/module/8189fs/parameters/rtw_ips_mode /sys/module/8189fs/parameters/rtw_power_mgnt /sys/module/8189fs/parameters/rtw_channel_plan
   gpioinfo gpiochip1 | grep 'line  13:'
   pidof wpa_supplicant udhcpc; ls -l /etc/fw_env.config
   ```
   Expect no wpa_supplicant running and GPIO45 (gpiochip1 line 13) unused.
2. `/etc/init.d/S55netd start` (or reboot); `pos wifi status` → `off`,
   `available yes`; `ls -la /var/lib/pocketos/netd` → absent (nothing written
   until turned on).
3. `pos wifi on` → `disconnected` within 5 s; `pos wifi status` shows
   `wpa3_supported` **false** (confirms the driver finding);
   `stat -c '%a %U' /var/lib/pocketos/netd /var/lib/pocketos/netd/wifi.conf`
   → `700 root`, `600 root`.
4. `pos wifi scan` → the test network is listed once with a plausible signal;
   compare with the phone's own scanner; note `hidden` count.
5. Wrong passphrase: `pos wifi connect <SSID>`, type a wrong one → `failed:
   auth_failed` within 30 s; `grep -c network= /var/lib/pocketos/netd/wifi.conf`
   → 0.
6. Right passphrase → `connected to <SSID>, ipv4 <addr>`; `ip addr show
   wlan0`, `ip route`, `cat /etc/resolv.conf`; `ping -c 3 -I wlan0 <gateway>`.
   Record which default route wins with eth0 also up.
7. Redaction: `grep -rF '<passphrase>' /var/lib/pocketos/log /run/pocketos`
   → nothing; `for p in $(pidof wpa_supplicant udhcpc); do tr '\0' ' '
   </proc/$p/cmdline; echo; done` → no passphrase.
8. Settings app: Wi-Fi section shows the same state, SSID, signal and address;
   Disconnect, then tap the saved network to rejoin without typing.
9. Reboot → Wi-Fi comes back on and rejoins by itself (`pos wifi status`
   within 60 s of boot). Record the time to `connected`.
10. Unplug Ethernet, reboot → confirm what the vendor `ifup wlan0` stanza
    does (serial log) and that netd is not `interface_busy`.
11. `pos wifi forget <SSID>` → disconnected, store has no network line.
12. `pos wifi off` → `ip link show wlan0` is DOWN, no wpa_supplicant or
    udhcpc left.
13. Coexistence (only if radiod runs the sx1262 backend and the owner wants
    it; receive only): `pos radio rssi` a few times with Wi-Fi idle, then
    again while Wi-Fi carries traffic (for example `wget` of a large file to
    /dev/null); record any change in the noise floor.

Deliberately not in the test: WPA3 (the driver cannot), enterprise, WEP,
access-point mode, and changing the regulatory domain.
