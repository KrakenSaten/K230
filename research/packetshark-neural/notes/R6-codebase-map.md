# R6 — Where an intelligence engine hooks into pos-capture (read-only map, master 448327d2 + PR #186)

Exploration by a specialist agent; file:line references are to the tree at 448327d2. Condensed.

## Per-packet facts (core/pocketpcap/ppc_record.h, 80-byte `struct ppc_record`, 147-170)

- `rel_ns` (ns since the session's first packet, clock-step corrected), `seq` (1-based, never reused), `wire_len`, `cap_len` (= bytes *stored*), `flags`, `cls`/`l3`/`l4`/`app`, `tcp_flags`, `info`, `sport`/`dport`, `signal` (low byte: 6 findings; high byte: 19 diagnosis codes), `src[16]`/`dst[16]`, `a`/`b` (TCP seq/ack; DNS id|flags, qd|an counts; DHCP xid, op|type; ICMP type|code ...).
- Flags: OUT, BROADCAST, MULTICAST, VLAN, FRAGMENT, IPV6, TRUNCATED, GRO, MALFORMED, NONFIRST.
- **Direction** is only `PPC_F_OUT` from `PPC_PKT_OUTGOING`; the **file source always gives UNKNOWN** (ppc_pcapfile.c:169).
- **Not in the record:** TCP window, TTL/hop limit, TCP options (the dissector parses MSS/WS values and names SACKOK/SACK/TS on demand), DNS query name/type (parsed on demand from stored bytes), VLAN id, the MACs of IP packets (overwritten by the IP addresses, ppc_decode.c:507-508 vs 346-347/410-411).

## The hook (tools/capture/pos_capture.c `on_frame()`, 566-609)

- Lines 590-606 see the whole captured frame (`f->data`, `f->cap_len`, snaplen 65535) **before** `ppc_store_len()` applies HEADERS at 607. A TLS ClientHello is visible there transiently.
- Existing analyzers: `ppc_signals_frame` (597-599, record + tcp_len) and `ppc_net_frame(&h->net, &r, f->data, f->cap_len, pay, seq)` (605, full bytes) — the natural pattern for a new analyzer.
- No analyzer runs in HOLD/SAVING (frames counted, not decoded, 575) or while shedding (592-595). Both call the "blind" paths.

## Time series that exist today

- `ppc_stats` bins: **only** `bins[120][8]` packet counts per class + `held_bins[120]`; **no bytes per bin**; bins keyed by monotonic seconds since START (pos_capture.c:2018-2020), a long gap is cut to 120 s.
- `struct ppc_diag` (36 figures, ppc_proto.h:331-372) and `struct ppc_net_totals` (33 figures, 407-445) are **cumulative**, emitted once a second as one snapshot. Per-second DNS/TCP timing must be derived from deltas of `dns_rtt_sum_us`/`dns_answered`, `tcp_hs_sum_us`/`tcp_timed` — i.e. a per-second **mean**, not a median, unless the engine keeps its own per-bin sketch.
- Drops: `kdrop`/`ifdrop` (0 for file and synth sources), `shed`, `held`, `ui_skipped`, `blinded`.

## Replay and fixtures

- `pos-capture session --source file:PATH[:PPS]` then `start file0 headers 0 all 0` (tests/pos_capture_test.sh:163-174). Unpaced = as fast as the loop; with PPS = paced by the monotonic clock. **No mode replays at recorded inter-packet speed; bins follow arrival time; the expiry "now" is real time from the file's first stamp; direction is lost.** A timeline replay needs a recorded-time clock mode.
- Synthetic source `synth:<pps>[:seed][:crash=N][:step=N,S]`: deterministic frame mix with periodic findings and DNS/TCP/DHCP/ARP transactions, evenly spaced stamps, **no scenario script**.
- Only one committed pcap (tests/data/packetshark/selftest.pcap, 602 B); others generated by tests/ppc_mkfixtures.c.

## Protocol and memory limits

- `PPC_PROTO_VERSION 5`; the shell kills a helper of another version (psk_session.c:338-343). Unknown words are ignored both ways. `PPC_LINE_MAX 1024`, `PPC_FIELDS_MAX 40` (diag uses 37, net 34) — a new figure set needs its own line. 64 KiB out queue; snapshot lines are dropped while anything is queued.
- Heap at START ≈ 22.5 MiB (store 5 MiB + 16 MiB ring, view 768 KiB, signals 712,704 B, net ≈ 37 KiB) + libpcap 4 MiB ring; measured peak RSS 23.2 MB; ADR-016 bound 32 MiB. **Headroom for a new engine ≈ 8 MiB before the bound, less the libpcap ring if it is counted.**

## Lint that a new engine meets (tests/packetshark_lint.sh)

Receive-only (no inject/send/raw sockets), one `<pcap` include, no printf/alloc in decode/stats hot path, single calloc in signals and net, no unbounded loops in decoder/net, no LVGL in library/helper, exactly two `O_CREAT` (lock, SAVE), packets written only to the save fd, nothing under /tmp, **no log line built from packet text**, psk_remote.c fields fixed. A new `core/pocketpcap/*.c` falls under the transmit, write and /tmp rules automatically; its own allocation and loop rules must be added.

## Vision's nncase backend (core/pocketvision/vision_kpu_nncase.cpp) — what a numeric net can reuse

- Inputs are `hrt::create(dt_uint8, shape, hrt::pool_shared)`; written with map/memcpy/unmap + `hrt::sync(..., sync_write_back, true)`; outputs via `output_tensor(i)` → `to_host()` → map → memcpy.
- Reusable: `pool_hold` / `release_pool()` (`shrink_memory_pool(); kd_mpi_mmz_deinit();`) and the `live` counter; load and output enumeration; `describe`.
- Image-specific: the `[1,3,H,W]` u8 input check, AI2D builder paths, BG3P frame format, pocketcam include.
- Build: `POCKETVISION_KPU=1` links `-lNncase.Runtime.Native -lnncase.rt_modules.k230 -lfunctional_k230 -lmmz`; tests/vision_lint.sh requires nncase headers in **only this file**. pos-capture links only `$(PPC_LIBS)` with `$(CC)` — so KPU inference must not go into pos-capture itself.
